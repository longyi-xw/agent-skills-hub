# 逆向分析

## 授权前置（必须先确认）

本技能仅用于**你有权分析的目标**：自有应用、获授权的渗透/研究对象、CTF 题目、公开样本、为兼容或排障而分析的对接方。

动手前先确认一句话：**「这个目标我为什么有权分析？」** 属于以下之一才继续——自研/自有、书面授权、竞赛环境、公开教学样本、为互操作/排障的最小必要分析。若是为了绕过他人付费墙、盗取账号、批量薅羊毛、去除他人版权保护或规避风控去做欺诈，则不做，并说明原因。

分析结论用于理解与修复/对接，不用于制作可直接滥用的攻击件。

## 分析路线：先静态摸清，再动态验证

```
1. 侦察    目标是什么：平台、语言、打包方式、有无加固
2. 静态    反编译/反汇编，定位关键函数与字符串，形成假设
3. 动态    运行时 hook / 抓包，验证或推翻假设
4. 固化    把稳定结论写成可复用脚本，附上定位依据
```

不要一上来就 hook 一切。先静态缩小范围，动态只用来验证少数几个关键点——这样最快也最稳。

## 工具链按目标选

| 目标 | 静态 | 动态 |
|---|---|---|
| Android App | jadx、apktool、Ghidra(so) | Frida、objection、Charles/mitmproxy |
| iOS App | Hopper/Ghidra、class-dump | Frida、frida-trace |
| 桌面二进制 | Ghidra、IDA、Binary Ninja | x64dbg/lldb、Frida |
| Web/JS | 反混淆、source map、AST | 浏览器断点、hook 全局函数 |
| 网络协议 | 抓包看结构 | mitmproxy 脚本改写、重放 |

优先用能脚本化的工具（Frida、mitmproxy、Ghidra 脚本），一次分析沉淀成可重跑的资产。

## 静态分析要点

- 先找**字符串**：错误提示、URL、密钥常量、日志文案往往直接指向关键函数
- 找**入口**：签名/加密通常挂在网络层拦截器、JNI 注册、`init` 阶段
- 记录**定位依据**：写清「因为字符串 X → 定位到函数 Y」，方便复核与下次复用
- 加固包先判断加固厂商，再决定脱壳方案；不要对着壳代码硬读

## 动态分析（Frida 为主）

典型工作流：

1. `frida-trace` 粗扫感兴趣的函数名/方法名，看哪些被调用
2. 写 hook 打印入参、返回值、调用栈，确认数据流
3. 需要时改返回值/参数，验证对业务的影响
4. 把稳定的 hook 收敛成一个带说明的脚本

hook 脚本原则：

- 每个 hook 上方注释「为什么 hook 它、期望看到什么」
- 打印要结构化（JSON），便于后续解析
- 对高频函数加开关或采样，别把日志刷爆
- 区分「观测用」和「篡改用」的 hook，篡改的默认关闭

## 常见对抗与应对

| 遇到 | 思路 |
|---|---|
| 反调试 / 反 Frida | 早期 hook 检测点使其恒返回「安全」；或用非注入式方案 |
| 证书绑定（SSL Pinning） | hook 校验函数返回 true / 用 objection 一键；不要去改系统证书链 |
| 字符串/控制流混淆 | 动态取运行时真实值，而非硬啃静态；反混淆脚本还原 |
| 完整性校验 | 定位校验点，理解校验范围，评估最小修改面 |
| 关键逻辑在 native | 用 Ghidra 反汇编 + Frida hook so 导出/内部地址对照 |

对抗只为完成合法分析目标，点到为止。

## 固化产出

分析完成后交付：

- **结论**：signing/加密/协议的算法与参数，用文字 + 伪代码说明
- **定位依据**：怎么找到的，别人能复现
- **可复用脚本**：Frida hook / mitmproxy 脚本 / 解密函数，带用法注释
- **边界说明**：脚本在什么版本、什么条件下有效

产出脚本建议放进本仓库 `script-development` 约定的结构里长期维护。

## 反面案例

| 不要这样 | 要这样 |
|---|---|
| 不问用途直接开搞 | 先确认「我为什么有权分析这个目标」 |
| hook 上千个函数看日志 | 静态缩小范围，动态只验证关键几个 |
| 一次性命令行糊完就丢 | 沉淀成带注释、可重跑的脚本 |
| 硬读加固/混淆后的代码 | 动态取运行时真实值 |
| 把结论包装成即用攻击件 | 结论用于理解、修复、对接 |
